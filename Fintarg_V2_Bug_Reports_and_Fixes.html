2. Detailed Bug Reports, Root Causes, and Code Fixes

BUG-01: Root Route (GET /) 404 Route Not Found on Vercel
Resolved in Commit 72ca725
File: backend/src/app.ts
Severity: High
Impact: Deployed API root appeared offline
Root Cause Analysis

The Express router only registered sub-routers (/api/auth, /api/records, etc.) and contained a catch-all 404 handler without registering a root handler for GET /.

Applied Fix

Added route handlers for GET /, GET /health, and GET /api with content negotiation supporting both browser visitors (rich HTML dashboard) and programmatic callers (JSON metadata).

BUG-02: Serverless Lambda Hang via MongoMemoryServer Fallback
Resolved in Commit 72ca725
File: backend/src/config/database.ts
Severity: Critical
Impact: 504 Gateway Timeouts on Vercel serverless functions
Root Cause Analysis

In local environments, MongoMemoryServer spawns a native MongoDB process when MONGODB_URI is absent. In Vercel serverless execution, binary spawning is blocked, causing the Lambda process to freeze indefinitely.

Applied Fix

Disabled memory server fallback when NODE_ENV === 'production' or process.env.VERCEL === '1', and guarded database connection with a strict 5-second timeout:

if (process.env.NODE_ENV === 'production' || process.env.VERCEL === '1') {
  throw new Error('MONGODB_URI is required in production environment.');
}

BUG-05: HttpError Status Field Mismatch in Error Middleware
Resolved in Commit 6c906ab
File: backend/src/middleware/errors.ts
Severity: High
Impact: 400/401/404 errors masked as generic 500 server errors
Root Cause Analysis

HttpError only defined statusCode: number, but Express middleware and standard error loggers inspected err.status. Because status was undefined, errors defaulted to 500.

Applied Fix
export class HttpError extends Error {
  readonly statusCode: number;
  constructor(statusCode: number, message: string) {
    super(message);
    this.statusCode = statusCode;
  }
  get status(): number {
    return this.statusCode; // Alias for Express error handlers
  }
}

  !_request.headers.accept?.includes('application/json');
