1. Design Principles
The target users are ordinary people managing a tight monthly budget, often on a phone. The design
therefore favours clarity and calm over decoration.
Principle
What it means on screen
Answer the main question first
The dashboard opens with one number: net position for this month, with a clear
warning if it is negative.
Plain language
Labels such as "Remaining money" and "Shortfall", not accounting jargon.
Mobile first
Designed for a 360 px screen, then widened for tablet and desktop.
Colour carries meaning, never
alone
Green = on track, amber = attention, red = problem. Always paired with text or an
icon.
Personal but consistent
The user picks the theme colour; layout, spacing and behaviour never change.
Two editions, one system
Basic shows fewer menu items; Business adds Advanced and company features.
2. Colour System
Colours are defined as tokens so the user's chosen theme colour (FR-8.2) replaces only the Primary
tokens.

8. Key Interaction Rules
 Situation
Design behaviour
Shortfall detected
Dashboard number turns amber/red, warning banner appears, one action offers
to record a loan (FR-5.3, FR-4.4).
Savings goal not feasible
Amber feasibility box explains why in one sentence and offers "Adjust goal"
(FR-6.5).
Theme change
Preview updates instantly; Save applies to all screens and devices (FR-8.2, FR-8.8).
Letter generation
Missing profile fields are listed with a link to fix them before the letter is produced.
Upload error
States the reason (type or size) and how to fix it; never a generic failure message.
Basic user meets a Business
feature
Feature is hidden, not greyed out, unless a plan upgrade is being promoted.
Reminders
In-app badge on Home; email on the due date and 3 days before.
9. Accessibility Checklist
  Text contrast at least 4.5:1, including on user-chosen themes.
 All controls reachable and usable by keyboard; visible focus ring.
 Every icon has a text label or accessible name.
 Status is never shown by colour alone.
 Form errors are announced to screen readers and shown next to the field.
 Supports browser text zoom up to 200% without breaking layout.
10. Handoff Notes
  These wireframes fix layout, hierarchy and behaviour; final visual polish (illustrations, icons, logo)
comes after the product name and branding are confirmed.
 Build the colour, spacing and Poppins type values in sections 2 and 3 as design tokens (CSS
variables) so themes work from day one.
 A Figma file can be produced from these pages; the components in section 4 are the starting
library.
 Screens still to design: add income/expense forms (mobile), loan and pawn forms, documents list,
medical section, admin panel.
